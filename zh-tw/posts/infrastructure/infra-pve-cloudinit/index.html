這台速度很快喔 這樣太危險～ 飛太遠～ 總是有酷酷的玩具可以玩好開心的。直接來兩張 BF3，兩張 CX7, 一張 CX8 可惜的是還有一張 CX8 不知道插哪跟另一張 BF3 加強版，測試就是這麼重成本QQ

因為要測試 RDMA 跟 CCL 相關的功能與行為研究，現在 server 好貴… 只能使用 VM 來直通網卡搞 IOT 測試了，蠻可惜沒辦法打效能的， 之後有機會再來分享真實的 AI server 跑起來是怎樣吧～ 反正有 Gaudi2,Gaudi3,MI300X,MI350X,… 這些可以用＾＾

手邊目前只有老舊的 server 上面跑 PVE 剛好要建立一堆虛擬機去直通網卡，所以來記錄一下，以防之後又忘記怎麼搞～

從很久以前搞維運的時候就知道 cloud init 了，可惜一直懶得去用，現在趁著個機會來體驗一下～

下載 Cloud Image

首先就是去下載 cloud image 專們用來做 cloud init 的～ 官方下載點 => 點我

這邊我使用 24.04 LTS 來當範例

wget -O /tmp/ubuntu-24.04.img https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img
qemu-img info /tmp/ubuntu-24.04.img

建立 VM & Template

沒錯，要先建立一個 VM 然後再轉成 Template 呦～

這邊我使用我的配置來當範例，每個人的 PVE 網路跟儲存應該都不太一樣的～ 以下我會使用指令的方式來建立，因為可以複製貼上比較快XD

新增 VM

注意的是要看你的環境網卡是什麼呦～

# 建立 ID 411 的虛擬機，配置 8GB RAM、4 核心 (host 模式)、連接至 vmbr1
qm create 411 --name "ubuntu-2404-tpl" --memory 8192 --cores 4 --cpu host --net0 virtio,bridge=vmbr1 --scsihw virtio-scsi-single

把 image 匯入 storage 中

儲存池這邊在我的環境是

# 將下載的映像檔匯入至 vm-data 儲存池
qm importdisk 411 /tmp/ubuntu-24.04.img vm-data

VM Hardware 相關設定

# 掛載剛匯入的系統碟為 scsi0 並啟用 iothread
qm set 411 --scsi0 vm-data:vm-411-disk-0,iothread=1

# 掛載虛擬 CloudInit 光碟機到 ide0
qm set 411 --ide0 vm-data:cloudinit

# 設定開機順序優先從 scsi0 啟動
qm set 411 --boot order=scsi0

# 啟用 QEMU Guest Agent（讓 PVE 網頁可以直接顯示 VM 的 IP 位址）
qm set 411 --agent enabled=1

# 調整預設硬碟大小至 50GB（Cloud-Init 首次開機會自動撐大內部系統分割區）
qm resize 411 scsi0 50G

Hardware 這邊要記得看一下有沒有 cloud init 的裝置，有了才可以去 VM 的 Cloud-Init 設定。 到這邊差不多把麻煩要狂點跟輸入的東西用指令搞定了，接下來可以回到 WebUI 來看看～

設定 VM Cloud-Init

在 Hardware 那邊添加完 cloud-init 裝置後就可以來設定了。 可以設定使用者帳密、DNS、ssh key、ip，這邊保留 IP 不設定，到時候 clone 後每台再去手動設定，或是可以使用自動化工具像是 Terraform 去設定也可以。

VM 轉換成 Template

去 VM 列表右鍵，然後選擇 Convert to Template，然後轉完後會看到圖示有變化，多了一個可愛的資料夾～

從 Template 複製出 VM

點選 VM 選單的 Template 右鍵一下，然後選擇 Clone 然後就會跳出一個選單，填一填就好了。

另外選單中有 Mode 這個我都習慣使用 Full Clone 也就是會有獨立的虛擬硬碟，環境切乾淨的好。除非只是想要短暫測試後刪掉，那就可以選 Link Clone。

檢查複製出來的 VM 設定

剛複製出來的 VM 設定會跟 Template 一樣沒有 IP，這邊再添加上去即可。

添加完成後要記得去上方的 Regenerate Image 來套用設定。

這樣就大功告成了～～～ 接下來只需要直接開機，就可以使用 cloud-init 原本的帳密去登入了，以後建立 VM 會超級快的！！！

測試開機

目前我的 PVE cluster 是全部 M.2 SSD 開機大概 25 秒，然後 cloud-init 大概 5 分鐘就做完了～

過去手動安裝會耗費超多時間在把 iso 檔案解壓縮並寫道硬碟，然後完成安裝後還要去 apt update 所有套件，耗時超久的…

登入 VM 後可以使用該指令查看是否 cloud-init 已經完成了。

cloud-init status --wait

有了 Cloud-Init 後，建立一台 VM 大概是 10 分鐘以內就可以有一台可以用了虛擬機了，超開勳的！！！

結論

雖然這個東西現在看應該已經很過時了，但維運或是像我這樣很常做實驗的，非常推薦弄一個 template 來讓之後作業更加快速省時間， 維運的話還可以再來看怎麼使用 Terraform 或是其他自動化 framework 來做 DevOps ~
